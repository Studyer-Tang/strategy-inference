# v0.6 时序接口性能记录

[原始记录](../benchmarks/results/time-series-0.6.json)对应 v0.6.0 Python 源码和 [benchmark runner](../benchmarks/time_series.py) 的 SHA-256。记录里的 `git_head_at_run` 是计时前的仓库 HEAD；工作树中的待发布源码由逐文件哈希绑定。旧版性能记录没有覆盖或混入本版数据。

## 测量范围

本机 macOS ARM64，Python 3.13.15、NumPy 2.5.3。六个任务在独立进程中串行执行，各预热一次，再取五次热调用的中位数。五个 BLAS 线程环境变量设为 `1`；没有独立测得运行库实际线程数。

输入生成、导入、指纹计算不计入耗时。比较接口使用已有回测，计时不包含生成该回测。内存另作一次预热后的 `tracemalloc` 测量，包含新输出与临时分配，排除已有输入、导入和进程自身；它不是进程 RSS。

| 任务 | 热调用中位数 / ms | 跟踪分配峰值 / KiB |
| --- | ---: | ---: |
| 平方损失，10,000 观测 × 20 模型 | 0.105 | 3125.78 |
| 三基线滚动回测，T=4096、H=12、step=4、958 起点 | 19.089 | 754.25 |
| 比较两个候选，958 起点、B=999、lead=1 | 24.214 | 1312.75 |
| 批量区间回放，100,000 步 | 143.713 | 4982.79 |
| 流式区间更新，100,000 步 | 123.162 | 0.83 |
| 流式区间更新，1,000 步 | 1.224 | 0.80 |

滚动回测使用 naive、drift 和周期为 12 的 seasonal naive，训练窗为 256。比较相对 naive 使用共享 stationary-bootstrap 时间索引。区间任务使用 `alpha=0.1, step_size=0.1, decay=0.6, scale=1, initial_quantile=0.5`。

流式 tracker 保存常数个状态；本记录测量两个长度的分配峰值。批量接口保存整段结果，因此空间随 T 增长。两个 100,000 步接口的终态、漏覆盖次数与覆盖相同；五次调用及独立核验的输出指纹一致。完整采样值、输入和结果指纹见原始 JSON。

这些是本机工程测量，不是跨硬件速度承诺，也不是检验水平、功效或覆盖校准的证据。回测 callback 的计算成本取决于接入模型。

## 复现

在 v0.6.0 对应源码 checkout 中运行，输出到新文件；runner 拒绝覆盖已有记录：

```bash
python benchmarks/time_series.py --output /tmp/time-series-local.json
```

环境不同可能改变计时、内存分配及浮点结果指纹。若需比较实现改动，应保留双方源码哈希、相同任务设置和原始重复样本。

[v0.5 冻结页面](library/v0.5.0/index.html)与[旧版性能说明](performance.md)只说明旧版均值推断接口的优化。
