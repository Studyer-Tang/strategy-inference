# 运行效率

0.5.0 改进计算与使用接口，不改变旧检验的统计定义、抽样次数、数值精度或认证预算。速度评价与统计校准是不同任务。

## 本机对照

同一 Python 环境，逐格隔离进程，基线为 `v0.4.0`（`b1feacc83585fd9c3258c653e7c97853ba1c3b1c`）。数据生成种子事先固定，测试四种计算路径；BLAS 单线程，每格一次首次调用及七次热调用，以中位数报告。输入为相同的 float64 矩阵。

环境：macOS 26.4 / ARM64，Python 3.13.15，NumPy 2.5.3，SciPy 1.18.1。数据生成、文件导出和绘图不计入调用耗时。

| 场景 | 0.4 热调用 / ms | 0.5 热调用 / ms | 倍数 | 0.5 统一接口热调用 / ms |
| --- | ---: | ---: | ---: | ---: |
| HAC 方差，512×20 | 0.06 | 0.07 | 0.99× | — |
| 固定尺度 bootstrap，512×20，B=1999 | 16.03 | 15.38 | 1.04× | 15.67 |
| 重估尺度 bootstrap，512×20，B=1999 | 160.09 | 74.63 | 2.15× | 74.66 |
| 重估尺度 bootstrap，1024×100，B=499 | 351.98 | 182.31 | 1.93× | 183.27 |
| 联合 Gaussian AR，512×20 | 50.90 | 21.18 | 2.40× | 21.24 |
| 联合 Gaussian AR，2048×100 | 136.69 | 76.75 | 1.78× | 76.91 |

重估尺度的 bootstrap 约快两倍，联合参数认证约快 1.8–2.4 倍。固定尺度与单独 HAC 方差的热耗时基本不变。统一入口还整理列名、只读结果与诊断；其时间单独测量，不通过两次独立计时相减来声称准确的封装开销。

这些是此机器、此输入和此软件环境的观测，不是跨硬件的速度保证。源码与环境、每次计时、首次调用、结果比较以及内存测量均在[完整基准记录](../benchmarks/results/library-0.5.json)中。

## 首次使用与缓存

`import strategy_inference` 只加载接口表。实际使用时才导入相应数值模块；CLI 的 `--help`、`--version` 不加载 NumPy 或 SciPy。Gaussian AR 认证不因本次优化新增 SciPy 导入；只计算带宽、HAC 方差或 bootstrap 样本时也不需要 SciPy 的分布模块。

记录中的 `import_ms`、`api_load_ms`、`cold_call_ms` 分别对应包导入、访问接口、首次核心调用。`first_use_ms` 是三者之和；worker 在计时前已导入 NumPy 并构造输入，因此它不包括 Python/NumPy 启动，也不是完整冷进程耗时。

Gaussian AR 的首次调用需要构造精确临界值。相同样本量、候选数和预算的后续调用可复用这些与数据无关的临界值缓存；热调用仍会重新计算输入数据的参数集合与认证。不会缓存用户收益矩阵或按已有结果跳过检验。

## 内存

Bootstrap 对抽样和候选列分块，内部按 16 MiB 的工作预算限制批次。预算不包含输入 `T×K`、返回的 `B×K` 抽样统计量、解释器及科学计算依赖；极长单列的一个样本是不可再分的最小单位，所以 16 MiB 不是整个进程的硬上限。不会默认分配完整 `B×T×K` 张量。

本次固定尺度 `512×20、B=1999` 的单次热调用峰值跟踪分配约由 4.97 MiB 降至 2.46 MiB；重估尺度的峰值基本持平。联合认证为复用 Gram 和 Bernstein 中间结果多保存少量信息：本次两格的峰值略增，完整记录保留了这一代价。

`traced_call_peak_mib` 是一次热核心调用新增的峰值跟踪分配，包含该次结果、不含已存在的输入与导入；`process_peak_rss_mib` 是整个 worker 的历史峰值，包含解释器、依赖和输入。二者不能混作同一个指标。

## 优化保持了什么

- Bootstrap 保持共享时间索引、float64、几何块长度、滞后权重、中心化与随机流。连续时间轴的求和顺序可带来约 1e-14 的浮点差；本次目标场景的所有边际、列级调整与全族 p 值同旧实现一致，不宣称任意恰落阈值的浮点输入逐位一致。
- Gaussian AR 复用精确前缀 Gram 与 de Casteljau 子区间系数。Student 的标准库近似仅提供搜索初值，最终临界值仍由整数 CDF 与外向相邻根确认。区间、行列式多项式、临界值、决定、节点数与未决标志在独立旧实现对照中逐字段一致。
- 没有缩小抽样数、降低认证深度、切换 float32 或跳过退化检查。新统一入口 bootstrap 默认 resampled，旧 `audit_returns` 默认 fixed；比较时明确使用同一模式。

[Bootstrap 对照与超大批次检查](../benchmarks/results/bootstrap-equivalence-0.5.json)和[52 个完整认证结果对照](../benchmarks/results/certified-equivalence-0.5.json)为补充工程记录。独立循环、旧算法根搜索、binary64 次正规数和精确多项式对照已纳入测试，性能阈值不作为硬件无关的单元测试断言。

## 重新测量

从源码目录安装开发依赖，然后运行：

```bash
python benchmarks/run.py --baseline v0.4.0 --repeats 7 --output benchmarks/results/local.json
```

需要本地存在基线 Git 标签。脚本临时提取其源码，每格按相同输入、种子和线程配置串行运行，不切换当前工作分支；同时检查结果等价性及候选源代码在测量期间是否改变。时间和峰值内存不会逐字节重复；应比较完整分布和明确的环境。
