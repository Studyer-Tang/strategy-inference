# 固定尺度融合的运行成本（v0.8）

当前实现按预先指定的权重融合自身步长 RMS 和最短步长共享 RMS。它在原成熟反馈队列之外增加 O(H) 当前来源状态；没有第二个权重学习器，也不保存成熟预测的历史。固定步长集合下，流式队列上限是各物理步长之和。本次四个步长为 1、6、12、24，末尾保留 43 条未成熟预测。

下面是本机串行工程测量。每项先做同输入批量/流式一致性检查、一次预热，再运行五次计时；另一次 warmed `tracemalloc` 调用测新增分配。原始记录包含全部样本、输入/结果指纹、终态、版本与完整源码哈希，见 [blended-scales-0.8.json](../benchmarks/results/blended-scales-0.8.json)。

| 任务 | 五次热调用中位数 | 新增分配峰值 |
| --- | ---: | ---: |
| 融合批量，12,000 × 4 | 207.887 ms | 4,983,712 B |
| 自身步长流式，50,000 × 4 | 672.818 ms | 19,536 B |
| 短步长共享流式，50,000 × 4 | 669.409 ms | 19,648 B |
| 半权重融合流式，50,000 × 4 | 753.591 ms | 20,864 B |
| 半权重融合流式，1,000 × 4 | 15.424 ms | 20,608 B |

同机 50,000 点融合比短步长共享多约 12.6% 时间和 1,216 B 峰值分配。两种长度下峰值接近，符合不保留成熟历史的实现；两个有限测量本身不证明渐近内存规律。峰值分配不是进程 RSS，也不包括已经存在的输入、导入或输出指纹计算。

环境为 macOS、Python 3.13.15、NumPy 2.5.3，各 BLAS 线程环境设为 1。输入为固定种子的平稳 Gaussian AR(.65)，点预测与初始尺度使用已知 DGP 参数；生成输入、模型公式、接口一致性检查和导出/哈希均在计时外。API 内部构造输出包含在计时中。批量接口保存整段发行数组，流式接口只保留当前状态、active lanes 和 pending。

性能任务使用标量 `step_size=0.1`；独立[统计研究](blended-scales-results.md)使用 `0.1/sqrt(lead)` 和训练数据拟合的滚动 AR 预测。这里不测模型训练成本，不是覆盖校准实验，也不能代表其他机器或所有数据上的速度。

源码稳定后可在新的输出路径复现：

```bash
python benchmarks/blended_scales.py --output /tmp/blended-scales-benchmark.json
```

程序逐项使用独立进程，固定线程数，拒绝覆盖已存在的输出，检查测量期间源码未变以及每次调用的结果指纹一致。v0.7 的[历史计时](multistep-performance.md)和 [v0.7 归档页面](https://studyer-tang.github.io/strategy-inference/library/v0.7.0/)继续绑定原发布源码。
