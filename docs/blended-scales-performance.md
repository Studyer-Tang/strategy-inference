# 固定尺度融合与维护重构的运行成本

当前实现按预先指定的权重融合自身步长 RMS 和最短步长共享 RMS。它在原成熟反馈队列之外增加 O(H) 当前来源状态；没有第二个权重学习器，也不保存成熟预测的历史。固定步长集合下，流式队列上限是各物理步长之和。本次四个步长为 1、6、12、24，末尾保留 43 条未成熟预测。

下面五项测量绑定 v0.8.0 发布源码，是冻结的历史记录。每项先做同输入批量/流式一致性检查、一次预热，再运行五次计时；另一次 warmed `tracemalloc` 调用测新增分配。原始记录包含全部样本、输入/结果指纹、终态、版本与完整源码哈希，见 [blended-scales-0.8.json](../benchmarks/results/blended-scales-0.8.json)。

| 任务 | 五次热调用中位数 | 新增分配峰值 |
| --- | ---: | ---: |
| 融合批量，12,000 × 4 | 207.887 ms | 4,983,712 B |
| 自身步长流式，50,000 × 4 | 672.818 ms | 19,536 B |
| 短步长共享流式，50,000 × 4 | 669.409 ms | 19,648 B |
| 半权重融合流式，50,000 × 4 | 753.591 ms | 20,864 B |
| 半权重融合流式，1,000 × 4 | 15.424 ms | 20,608 B |

同机 50,000 点融合比短步长共享多约 12.6% 时间和 1,216 B 峰值分配。两种长度下峰值接近，符合不保留成熟历史的实现；两个有限测量本身不证明渐近内存规律。峰值分配不是进程 RSS，也不包括已经存在的输入、导入或输出指纹计算。

环境为 macOS、Python 3.13.15、NumPy 2.5.3，各 BLAS 线程环境设为 1。输入为固定种子的平稳 Gaussian AR(.65)，点预测与初始尺度使用已知 DGP 参数；生成输入、模型公式、接口一致性检查和导出/哈希均在计时外。API 内部构造输出包含在计时中。批量接口保存整段发行数组，流式接口只保留当前状态、active lanes 和 pending。

性能任务使用标量 `step_size=0.1`；独立[统计研究](blended-scales-results.md)使用 `0.1/sqrt(lead)` 和训练数据拟合的滚动 AR 预测。这里不测模型训练成本，不是覆盖校准实验，也不能代表其他机器或所有数据上的速度。

逐字节复核以上记录时使用 v0.8.0 标签；在当前源码运行下列命令会生成当前版本的新测量：

```bash
python benchmarks/blended_scales.py --output /tmp/blended-scales-benchmark.json
```

程序逐项使用独立进程，固定线程数，拒绝覆盖已存在的输出，检查测量期间源码未变以及每次调用的结果指纹一致。v0.7 的[历史计时](multistep-performance.md)和 [v0.7 归档页面](https://studyer-tang.github.io/strategy-inference/library/v0.7.0/)继续绑定原发布源码。


## v0.8.1 与 v0.8.0 的同输入对照

维护重构不改变统计方法。审计入口将已检查的数据传给内部计算函数，完整矩阵校验从四次减为一次；公共函数各自仍严格校验输入。多步汇总与公开 interval score 使用同一评分实现，批量计算宽度和分数后保留原缩放 `math.fsum` 均值。已有反馈 lane 不再反复构造用不到的默认对象。

[原始对照](../benchmarks/results/refactor-0.8.1.json)由同一驱动分别在 v0.8.0 Git 源码和当前源码的独立、串行进程中运行。五次热调用中位数如下；单位为 ms。

| 任务 | v0.8.0 | v0.8.1 |
| --- | ---: | ---: |
| 固定尺度 bootstrap，512 × 20，B=1999 | 16.024 | 15.757 |
| 重估尺度 bootstrap，1024 × 100，B=499 | 185.674 | 185.443 |
| 固定尺度 bootstrap，8192 × 100，B=39 | 12.100 | 9.399 |
| 多步结果汇总，11976 × 4 | 25.004 | 3.159 |
| 多步融合流式，12000 个观测、11976 个发行起点 × 4 | 182.781 | 157.839 |

本次汇总约快 7.9 倍，流式耗时降低约 13.6%；汇总新增分配峰值由约 1.202 MiB 降到 0.748 MiB，流式约 20.64 KiB，两版本相同。8192 × 100 的低 B 工程负载减少约 22.3% 耗时；B=39 用于观察校验成本，不是推荐的统计模拟精度。较小 fixed 负载和重估尺度负载的差别很小，不能声称所有 bootstrap 都明显加速。

环境为 macOS、Python 3.13.15、NumPy 2.5.3、SciPy 1.18.1，五个 BLAS 线程环境均设为 1。基线与候选在每项任务内使用同一种子、数据和参数。多步任务使用固定的 φ^h y_t 点预测基线和指定几何初始化尺度；计时没有拟合模型或评价它们的统计校准。输入生成、导入、汇总所需结果的预先构造及输出指纹都在计时外；流式任务计入 tracker 创建和反馈/发行，在末尾停止发行以使全部区间成熟。另一次热调用记录 tracemalloc 峰值，排除预先存在的输入和结果，不是 RSS。原始记录另列导入、准备和首调用时间；它们不是这张热调用表。

对照保存两版完整 Python 源码哈希和驱动哈希。bootstrap 决定、p 值精确一致，报告的数值字段最大差为零；多步汇总与完整流式终态的 SHA-256 一致。指纹不构成所有输入的等价证明，边界、原子失败、随机数位置与反馈状态另由回归测试检查。

```bash
python benchmarks/run.py --baseline v0.8.0 --repeats 5 \
  --cases bootstrap_fixed_512x20 bootstrap_resampled_1024x100 bootstrap_fixed_8192x100 multistep_summary_12000x4 multistep_stream_12000x4 \
  --output /tmp/refactor-benchmark.json
```
